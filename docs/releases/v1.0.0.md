# ZeroTrust-FL-Sim v1.0.0

ZeroTrust-FL-Sim v1.0.0 is the first production release line for the supported federated-learning simulation profile. Publication is intentionally fail-closed: the tag workflow must verify repository protection, independent security-review evidence, OpenSSF application evidence, exact release metadata, and all release tests before artifacts are published.

## Supported production profile

The supported aggregation path is CPU/PyTorch/native C++ using the validated PyTorch CPU and C++20 Byzantine-robust aggregation implementations. The supported deployment evidence covers the Go coordinator, Python/PyTorch workers, durable PostgreSQL/S3 recovery, immutable OCI images, Docker integration, and Helm deployment to an ephemeral Kind/Kubernetes cluster with CI-only PKI.

CUDA remains experimental unless a real CUDA device executes `scripts/capture_cuda_parity_evidence.py` and a reviewed evidence artifact is linked in `release/v1.0-evidence.json`. CPU-only or skipped CUDA tests are not CUDA validation.

## Security and trust boundaries

The coordinator enforces authenticated enrollment, registration lifecycle controls, replay defenses, explicit protocol/model/schema identity, bounded update payloads, durable experiment identity, and durable model identity. Durable state schema v3 fails closed when persisted `model_id` does not match runtime configuration.

Byzantine-robust aggregation remains subject to each algorithm's documented population and adversary bounds. Differential privacy and CKKS are separate implemented paths; the ordinary gRPC update path must not be described as end-to-end homomorphically encrypted.

## Reproducibility and operations

Release evidence includes exact-commit benchmark manifests, runtime facts, configuration digests, CPU/native parity tests, deterministic failure/recovery coverage, Docker restart recovery, real Kind/Kubernetes E2E, SBOM generation, keyless Sigstore/Cosign signing, and build-provenance attestations.

v1.0.0 must not be published until all canonical external/admin gates are satisfied and linked with evidence:
