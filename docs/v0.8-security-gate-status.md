# v0.8 Security Gate Status

This document separates repository-owned automated hardening from external production-readiness evidence.

## Implemented in issue #69

- Python dependency audit with pip-audit
- Go reachable-vulnerability audit with govulncheck
- npm runtime dependency audit
- Go and Python static security analysis
- repository secret scanning
- reviewed direct-dependency license policy
- HIGH/CRITICAL container vulnerability gates for coordinator, worker, and recovery images
- Go NumPy/model decoder fuzzing
- C++ Byzantine aggregation libFuzzer runs with AddressSanitizer and UndefinedBehaviorSanitizer
- immutable OCI digest release metadata
- source and OCI SPDX SBOMs
- keyless Sigstore/Cosign signatures
- OCI SBOM attestations
- GitHub build-provenance attestations
- retained release checksums/evidence
- recurring OpenSSF Scorecard evidence
- NIST SSDF engineering-practice mapping without a certification claim
- independent-review reproduction/reporting checklist

## External gates that remain open

The following cannot be satisfied by repository-owned CI alone:

- issue #37: protect `main` and require release/security checks using repository administration controls;
- issue #70: independent security assessment or independently reproduced review evidence;
- OpenSSF Best Practices application/enrollment with a real external application record.

Do not claim v0.8/v1.0 production security acceptance from the automated controls alone. The release candidate must satisfy the external gates and all later roadmap gates as well.
